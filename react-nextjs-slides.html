React.js

Die UI-Library, die alles verändert hat

Was ist React?

React ist eine JavaScript-Library von Meta für deklarative UI-Entwicklung.

Die 3 Kernprinzipien

⚛️ Components — Wiederverwendbare UI-Bausteine

📦 Props — Daten von außen (read-only)

🔄 State — Interne, veränderliche Daten

<App> <Header> <Logo /> <Nav /> </Header> <ProductGrid> <ProductCard title="Laptop" price={999} /> <ProductCard title="T-Shirt" price={29} /> </ProductGrid> </App>

Imperativ vs. Deklarativ

❌ Imperativ (klassisches DOM)

// Du SAGST dem Browser WIE er es tun soll
const list = document.getElementById('list')
list.innerHTML = ''
products.forEach(p => {
  const li = document.createElement('li')
  li.textContent = p.title
  list.appendChild(li)
})
// Problem: du musst den DOM-Zustand
// selbst verwalten

✅ Deklarativ (React)

// Du BESCHREIBST WAS du willst
// React kümmert sich um das WIE
function ProductList({ products }) {
  return (
    <ul>
      {products.map(p => (
        <li key={p.id}>{p.title}</li>
      ))}
    </ul>
  )
}
// products ändert sich → React
// aktualisiert nur was sich änderte
Virtual DOM: React vergleicht alten und neuen VDOM — aktualisiert nur die Unterschiede im echten DOM

JSX — JavaScript + HTML-Syntax

  const isExpensive = price > 100

  return (
    // Ein Root-Element (oder Fragment <>)
    <div className="card">
      <h3>{title}</h3>

      {/* Bedingtes Rendering */}

      <p>
        {isExpensive ? '💎' : '💰'}
        €{price.toFixed(2)}
      </p>
    </div>
  )
}

State & Events — useState

'use client'
import { useState } from 'react'

function Counter() {
  // [Wert, Setter-Funktion]
  const [count, setCount] = useState(0)

  return (
    <div>
      <p>Zähler: {count}</p>
      <button onClick={() =>
        setCount(count + 1)
      }>

      </button>
    </div>
  )
}

React Hooks — Übersicht

useState — Lokaler State

const [val, setVal] = useState(init)

useEffect — Seiteneffekte

API-Calls, DOM-Manipulation, Subscriptions — läuft nach dem Render

useContext — Globale Daten

Daten ohne Prop Drilling durch den Component-Tree reichen

useMemo — Berechnungen cachen

Teures Ergebnis nur neu berechnen wenn Abhängigkeiten sich ändern

useCallback — Funktionen cachen

Referenz-Stabilität für Event Handler (verhindert unnötige Re-Renders)

Custom Hooks — Logik teilen

useProducts(), useCart() — eigene Hooks für wiederverwendbare Logik

Hook-Regeln: Nur auf Top-Level aufrufen · Nie in Schleifen oder Bedingungen

useEffect — Datenfetching

'use client'
import { useState, useEffect } from 'react'

function ProductDetail({ id }: { id: string }) {
  const [product, setProduct] = useState(null)
  const [loading, setLoading] = useState(true)

  useEffect(() => {
    let cancelled = false                          // verhindert Update bei Unmount

    fetch(`https://fakestoreapi.com/products/${id}`)
      .then(res => res.json())
      .then(data => { if (!cancelled) setProduct(data) })
      .finally(() => { if (!cancelled) setLoading(false) })

    return () => { cancelled = true }             // Cleanup
  }, [id])                                         // ← Dependency: läuft neu bei id-Änderung

  if (loading) return <div className="animate-pulse h-8 bg-gray-200 rounded" />
  return <h1>{product?.title}</h1>
}

//  useEffect(() => { ... })           → läuft bei JEDEM Render
//  useEffect(() => { ... }, [])       → läuft nur beim ersten Render
//  useEffect(() => { ... }, [value])  → läuft wenn value sich ändert
In Next.js Server Components: await fetch(url) direkt — kein useEffect nötig!

Server vs. Client Components

🟢 Server Component (Default)

Kein 'use client' Direktiv nötig

  • ✓ Async/Await direkt
  • ✓ Direkter DB-Zugriff
  • ✓ Kein JS im Browser
  • ✓ Kleines Bundle
  • ✗ Keine React Hooks
  • ✗ Keine Browser-APIs

🟠 Client Component

'use client' an die erste Zeile

  • ✓ useState, useEffect etc.
  • ✓ onClick, onChange etc.
  • ✓ localStorage, window
  • ✓ Zustand-Store Hooks
  • ⚠ JS wird an Browser gesendet
Faustregel: Default Server Component. Erst 'use client' wenn Interaktivität oder Browser-APIs gebraucht werden.

Rendering-Strategien

CSR — Client Side
HTML leer, JS holt Daten im Browser
✓ Dashboards hinter Login
✗ Schlechtes SEO, langsam
SSR — Server Side
HTML bei jedem Request auf dem Server
✓ Personalisierte Seiten
✗ Jeder Request kostet CPU
SSG — Static Gen
HTML beim Build generiert, CDN-auslieferbar
✓ Schnellstes Laden, günstig
✗ Daten sind statisch
ISR — Incremental SR lean-commerce
SSG + automatische Revalidierung
✓ Schnell UND frisch
✓ Perfekt für Shops!

ISR in der Praxis

// app/page.tsx — lean-commerce Homepage
// Datei: lean-commerce/apps/storefront/app/page.tsx

// ← Diese eine Zeile aktiviert ISR!
export const revalidate = 60   // Seite alle 60 Sekunden regenerieren

export default async function HomePage() {
  return (
    <main className="max-w-7xl mx-auto px-4 py-8">
      {/* Suspense: Wetter-Daten streamen separat */}
      <Suspense fallback={<WeatherSkeleton />}>
        <WeatherWidget />       {/* async Server Component */}
      </Suspense>

      {/* Produkte streamen unabhängig vom Wetter */}
      <Suspense fallback={<ProductsSkeleton />}>
        <FeaturedProducts />   {/* async Server Component */}
      </Suspense>
    </main>
  )
}

// On-Demand Revalidierung per Webhook:
// POST /api/revalidate → revalidatePath('/') → sofort neu generiert

State Management — Zustand

// lib/store/cart.ts — lean-commerce Warenkorb
// Datei: lean-commerce/apps/storefront/lib/store/cart.ts
import { create } from 'zustand'
import { persist } from 'zustand/middleware'
import { immer } from 'zustand/middleware/immer'

export const useCartStore = create<CartStore>()(
  persist(                  // ← State in localStorage
    immer((set, get) => ({  // ← Immer: mutierende Syntax erlaubt
      lines: [],

      addLine: (item) => set(state => {
        const existing = state.lines.find(l => l.productId === item.productId)
        if (existing) {
          existing.quantity += 1   // sieht mutierend aus, ist aber unveränderlich!
        } else {
          state.lines.push({ ...item, quantity: 1 })
        }
      }),
    })),
    { name: 'lean-commerce-cart' }  // localStorage Key
  )
)

// Verwendung in Client Component:
'use client'
const count = useCartStore(state => state.totalItems())

CI/CD Pipeline — GitHub Actions

# .github/workflows/deploy.yml
name: Deploy to AWS ECS
on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Configure AWS credentials
        uses: aws-actions/configure-aws-credentials@v4
        with:
          aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
          aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          aws-region: eu-central-1

      - name: Build & Push to ECR
        run: |
          docker build -t $ECR_URI:${{ github.sha }} .
          docker push $ECR_URI:${{ github.sha }}

      - name: Deploy ECS Service
        uses: aws-actions/amazon-ecs-deploy-task-definition@v1
        with:
          service: storefront
          cluster: lean-commerce

Best Practices

Was du im Produktion unbedingt beachten musst

Code-Qualität & Performance

Code-Qualität

  • TypeScript-Fehler null halten, kein any
  • Props mit Interfaces typisieren
  • key bei Listen: stabile IDs (nicht Index)
  • Default Server Component, 'use client' nur wenn nötig
  • Fehlerbehandlung in async Server Components
  • next/image für alle Bilder
  • next/link für alle Links

Performance

  • Parallele Fetches mit Promise.all()
  • Suspense-Grenzen für paralleles Streaming
  • ISR statt SSR wenn möglich
  • Cache-Tags für gezielte Invalidierung
  • useMemo/useCallback nur wenn gemessen nötig
  • Bundle-Analyse: @next/bundle-analyzer

Sicherheit & AWS-Checkliste

🔒 Sicherheit

  • Secrets nur via Secrets Manager
  • REVALIDATE_SECRET für Webhooks
  • Input-Validierung in Server Actions (zod)
  • Security Headers in next.config.mjs
  • HTTPS-only (ALB + CloudFront)
  • WAF-Regeln für ALB/CloudFront
  • ECR-Images: Vulnerability Scan

☁️ AWS Deployment

  • Dockerfile multi-stage (builder + runner)
  • Non-root User im Container
  • Health Check /api/health
  • CloudWatch Log Group + Alarme
  • Auto Scaling Policy
  • ALB mit HTTPS + ACM-Zertifikat
  • CloudFront vor ALB
  • GitHub Actions CI/CD Pipeline
